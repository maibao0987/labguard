# 循序開發與 Codex 接續提示詞

初始實作已包含階段 0～7 的核心功能，但實測程度依 verification.md。不要把程式存在與完整驗收等同。

共通前綴：

> 請先閱讀 AGENTS.md、README、docs/architecture.md 與 docs/verification.md。僅操作本人本機固定資產，不掃描外部主機，不推送或部署。逐項完成當前階段，記錄實際測試與未驗證事項。

## 階段 0：文件
「檢查威脅模型、架構及授權聲明是否與現有程式一致。補齊需求對照、MVP 完成條件及信任邊界，不啟動掃描。」

## 階段 1：Docker
「在已安裝 Docker Desktop 的環境驗證 Compose。確認 localhost bind、資料庫未發布、網路分隔、非 root、資源限制及無主機掛載。只使用自建假服務驗證邊界，保留 Docker inspect 證據。不探測真實外網。修復啟動問題並更新驗收紀錄。」

## 階段 2：安全基準
「驗證登入、搜尋、任務、留言、個人資料與 Alice/Bob/admin 權限矩陣。保持 fixed 模式安全。為實際缺陷補有效測試，不為單純格式修改增加測試。」

## 階段 3：漏洞與修復
「審查 SQLi、Stored XSS、IDOR 案例。先建立基準，再在隔離假資料中重現，說明根因及修復差異。XSS 不外傳資料，區分 HTML 注入與瀏覽器執行證據。保留正常功能回歸。」

## 階段 4：平台
「檢查匯入、去重、觀測與狀態歷史。為列表加入分頁、嚴格 JSON Schema 或適當的資料驗證。保持所有證據為不可信文字，加入與真實風險對應的測試。」

## 階段 5：Worker
「在 PostgreSQL 下驗證單 worker 領取、scope 撤銷、取消、逾時、中斷恢復、指紋去重的交易行為。使用自建 mock 服務，不擴大固定目標或加入任意命令。」

## 階段 6：複測與報告
「完成原資產修復的實際端到端展示：漏洞版偵測、人工確認、修復原服務、原資產複測、關閉、匯出。測試失敗或檢查未執行不能關閉。改善報告可讀性並保持不可信內容安全。」

## 階段 7：CI 與作品集
「在 GitHub 的隔離 CI 驗證 SQLite 與 PostgreSQL/Docker。凍結 Alembic baseline，拆分 DB migration 與 runtime 最小權限，建立依賴及映像檢查，記錄刻意漏洞與非預期問題，不全面忽略安全檢查。不自動推送或發布。」

建議每週 6～10 小時，依初始規格逐步練習；自動產生的程式仍需自己理解與操作。
